## 1. 环境准备

| | |
|---|---|
| 系统 | Windows 10 / 11（64 位） |
| Python | 3.8+，开发时用的是 3.11.9 |
| 第三方库 | **运行时零依赖**。`pip install` 一个都不需要 |
| 打包 | `pip install pyinstaller`（只有发版才用） |

```bash
git clone https://github.com/KagurazakaChizuru/dafeiyu-live-notify.git

copy config.example.json config.json
copy _account.txt.example _account.txt
```

以及一个 QQ 小号。**这两样都不进仓库**（原因见 [技术文档 §15](技术文档.md#15-许可证边界)）。

> ⚠️ `napcat/`、`qq-napcat/`、`config.json`、`_account.txt`、`*.exe`、`logs/`
> 都已在 `.gitignore` 里。提交前请务必确认没把 QQ 程序文件或你的真实群号带进去。

## 3. 必须遵守的工程约定

这几条都是**踩过坑才定下来的**，改代码时别绕开。

### 3.1 运行时零第三方依赖

`live_notify.py` / `triggers.py` / `gui.py` **只允许 import 标准库和 tkinter**。
WebSocket 客户端、PNG 编码、ICO 组装、HTTP 轮询全都是手写的。

引入任何一个 pip 包都会让"绿色免安装、解压即用"这个卖点失效。
**需要新能力时，先想能不能用标准库 + Win32 API 解决。**

### 3.2 数据目录必须用 `sys.executable` 推

```python
def _resolve_data_dir():
    if getattr(sys, "frozen", False):
        return os.path.join(os.path.dirname(os.path.abspath(sys.executable)), "app")
    return os.path.dirname(os.path.abspath(__file__))
```

打包成 onefile 之后 `__file__` 指向**临时解包目录**（`%TEMP%\_MEIxxxx`），
拿它找 `config.json` / `napcat/` 必然找不到。所以冻结态一律走 `sys.executable`。

### 3.3 读配置一律 `utf-8-sig`

```python
json.load(open(path, encoding="utf-8-sig"))
```

记事本写出来的 JSON 带 UTF-8 BOM，普通 `utf-8` 读会把 BOM 当成第一个字符，
`json.load` 直接报错。

### 3.4 访问 127.0.0.1 必须绕开系统代理

```python
opener = urllib.request.build_opener(urllib.request.ProxyHandler({}))
```

机器上开着 Clash / 加速器时，系统代理会把 `127.0.0.1:3000` 的请求也劫走，
表现为 NapCat 返回 HTTP 502 —— 看起来像 NapCat 坏了，其实是代理。

### 3.5 日志字体必须含中文字形

日志框是深色的。用 Consolas 这类纯西文字体时，Tk 会对缺失的中文字形做系统回退，
而**回退出来的字是画在一小块浅色底上的** —— 深色日志里会一条条冒白补丁。
`pick_log_font()` 优先挑中文等宽字体，就是为了这个。

### 3.6 停止 NapCat 只能按路径过滤

```powershell
Get-Process QQ | Where-Object { $_.ExecutablePath -like '*qq-napcat*' }
```

**绝不允许** `Stop-Process -Name QQ` —— 那会把用户自己的 QQ 一起杀掉。

### 3.7 PowerShell 脚本的编码

`.ps1` 里写中文**必须带 BOM**，否则 Windows PowerShell 5.1 会按 ANSI 解码，
中文注释被拆坏后直接抛 `Missing ')' in function parameter list`。

**但更省事的做法是干脆写英文。** 原因：

- 编辑工具重写文件时会**吃掉 BOM**。一个今天跑得好好的脚本，明天改一行就
  崩了，而且报错信息和编码八竿子打不着，极难排查
- 这个环境的 PowerShell 控制台本来就把中文输出成乱码，写英文反而看得清

所以约定：

| 文件 | 约定 |
|---|---|
| `.bat` | **纯 ASCII**（cmd 按 OEM 代码页读，中文会让字节偏移错位） |
| `.ps1` 里频繁改的（如 `_release.ps1`） | **纯 ASCII** |
| `.ps1` 里基本不动的（如 `_build/_makeicon.ps1`） | 可以用中文，但**必须带 BOM**，且编辑后要补回来 |

需要中文时用 unicode 转义，照样能保持源码是 ASCII：

```powershell
$dash = [string][char]0x2014 + [string][char]0x2014     # ——
$t = $t -replace '[\u3002\uFF01\uFF0C]+$', ''            # 去掉句末的 。！，
```

## 4. 调试手段

### 无界面跑核心逻辑

```bash
python live_notify.py check     # 自检：配置 / NapCat 连通性 / 群权限
python live_notify.py test      # 彩排：打印将发送的内容，不真发
python live_notify.py send      # 立即发送一次
python live_notify.py watch     # 常驻监控
python live_notify.py groups    # 列出机器人所在的所有群
```

加 `--config 别的路径.json` 可以指定配置文件。

### 不连真 QQ 也能调

`_mock_napcat.py` 是一个假的 OneBot 服务端，起在 3000 端口，
把所有请求打印出来并返回合理响应。改发送逻辑时用它，不用真的登录 QQ。

### 只调触发源

```bash
python _watchtest.py
```

用来单独验证 OBS 事件 / 快捷键 / 轮询是否正常触发。

### 界面

| 脚本 | 用途 |
|---|---|
| `启动界面.bat` | 正常启动（无控制台窗口） |
| `启动界面-调试.bat` | **带控制台启动**，`print` 和异常都能看见 |
| `退出全部.bat` | 强制收尾：关通知器 + 关 NapCat，不碰用户自己的 QQ |

界面里的「运行日志」标签页和 `app/logs/notify-YYYYMMDD.log` 是同一份内容。

> 冻结态下 `sys.stdout is None`，直接 `print()` 会抛异常。
> `_setup_console()` 会把 stdout 重定向到 devnull，所以 print 在两种形态下都安全。

## 5. 扩展指南

### 5.1 加一个触发源

**契约**：触发源是一个线程（或一个 `tick()` 轮询器），
在"确认开播"时调用传入的 `fire_callback(reason)`。
**冷却不要自己管** —— 开播侧所有触发源共用外层一个 `CooldownGate`，
各自限流会导致"OBS 点开播 + 顺手按了快捷键"发两遍。

步骤：

1. 在 `triggers.py` 里写一个新类，构造时接收 `fire_callback`
2. 在 `cmd_watch()`（`live_notify.py`）里实例化并 `start()`
3. 在 `gui.py` 的「触发方式」页加一个勾选项和状态标签
4. 在配置里加一个开关字段，并在 `load_config()` 里补默认值
5. 在 `docs/技术文档.md` §5.1 的触发源规格表里补一行

> 参考 `ObsWatcher`：它就是"连一个外部事件源，收到事件就回调"的标准形态。

### 5.2 加一个直播平台

目前只实现了 B站（`BilibiliRoom` + `PlatformWatcher`）。
加平台时注意，平台之间的差异只有两点：

- **怎么从用户填的链接里认出房间号**（参考 `guess_bilibili_room_id`）
- **怎么查开播状态，以及状态码怎么映射**

状态语义必须收敛到同一套：

| 值 | 含义 | 触发开播 | 触发下播 |
|---|---|---|---|
| `0` | 未开播 | ✅（0→1 跳变） | ✅（1→0 跳变） |
| `1` | 直播中 | — | — |
| `2` | 轮播 / 自动重播 | ❌ | ❌ |

`2` **绝对不能触发下播** —— 那是自动重播，不是人下播。

### 5.3 改消息格式

消息是**消息段数组**，不是纯字符串：

```python
[{"type": "at", "data": {"qq": "all"}}, {"type": "text", "data": {"text": " "}}, ...]
```

关键细节：**每个 `at` 段后面必须紧跟一个 text 段**（哪怕只有一个空格），
否则某些 QQ 客户端会把 @ 和后面的正文粘在一起显示。
`build_message()` 已经处理了这点，改的时候别丢。

### 5.4 加一个界面设置项

1. `_build_*_tab()` 里加控件，绑定到一个 `tk.StringVar` / `BooleanVar`
2. `_ui_to_cfg()` 里把控件值写回 `self.cfg`
3. `_cfg_to_ui()` 里做反向填充（重载配置时要用）
4. `load_config()` 里补默认值
5. 如果这一页变高了不用管 —— `ScrollFrame` 会自动出滚动条

## 6. 测试

```bash
python _selftest.py       # 17 组（覆盖内容见技术文档 §12.2）
python _watchtest.py      # 触发源联调（独立脚本，不在上面 17 组里）
python -m py_compile live_notify.py triggers.py gui.py   # 语法检查
```

`_selftest.py` 的组数和断言数**随代码变**，别照抄文档里的数字去核对 ——
跑一遍，数输出里的 `[PASS]` / `[FAIL]` 行才是准的
（写这份文档时是 17 组、`PASS=210 FAIL=0`，退出码 0）。
`_watchtest.py` 不在这个统计里，它是单独一个脚本。

改完之后**至少手动过一遍**这几条关键回归路径：

| 场景 | 期望 |
|---|---|
| 只勾「直播间开播时通知」，开播 | 发一条，@全体成员生效 |
| 新订阅一个 UP 主后第一次轮询 | **一条都不发**（只记基线），日志里明说"不补发历史" |
| 同一个 UP 主第二次轮询前发了新视频 | 只发新那条；积压超过 3 条时只发最新的并记 WARN |
| 订阅的 UP 主发了一条**投稿类**动态 | **不发** —— 同一个视频已经由投稿那一路报过了 |
| 动态的 SESSDATA 过期 | **不报错、只是没有动态**（实测）—— 靠 `check` 里那次官方号对照暴露出来，别的通知照常 |
| 同时勾直播间和 OBS，开播 | **只发一条** |
| 只播 10 分钟就下播 | 下播通知照常发（不被开播冷却吃掉） |
| 直播中断流 30 秒后恢复 | **不发**下播通知（宽限期兜住） |
| 房间状态是轮播（2） | 不触发开播，也不触发下播 |
| 程序启动时房间已经是开播状态 | **不补发**，只等下次跳变 |
| 关闭程序 | 用户自己的 QQ 进程**一个都不能少** |

最后一条是安全红线，动 `stop_napcat()` 之后必须验 ——
**自检里没有这一条的自动化用例**（技术文档 §6.5），所以只能靠人。

## 7. 打包与发版

```bash
pip install pyinstaller
python -m PyInstaller --noconfirm --clean --onefile --windowed ^
  --icon _build\app.ico ^
  --add-data "_build\app.ico;." ^
  --add-data "_build\header-light.png;." ^
  --add-data "_build\header-dark.png;." ^
  --version-file _build\version_info.txt ^
  --name "大肥鱼直播姬" ^
  gui.py
```

**`--add-data` 有三行，各管一件事**：图标、浅色头图、深色头图。

> ⚠️ **这里原先写的是 `--add-data "_build\mascot.png;."`，而仓库里根本没有
> `_build\mascot.png`**（`_build/` 下只有 `app.ico`、`header-light.png`、
> `header-dark.png`、`banner-art.png`、`icon-preview.png`、`version_info.txt`
> 和两个 `.ps1`）。照抄旧命令，PyInstaller 会因为源文件不存在直接失败。
> 那个"头部主视觉立绘 / 界面右上角"的说法也早就过时了 —— 现在没有立绘，
> 头图是**整条横幅**。

**头图的真实机制**（`gui.py` 的 `load_header_image()`，以源码为准）：

| | |
|---|---|
| 文件 | `header-<主题>.png`，也就是 `header-light.png` / `header-dark.png`；另有一个通用的 `header.png` 作为兜底 |
| 放哪 | 先找程序目录（`app\`，也就是 `HERE`），再找 `sys._MEIPASS`（onefile 的解包目录），最后找 `_build\` |
| 尺寸 | 780 × 138（**程序不做缩放**：tkinter 只能整数倍缩，硬缩更糟；图按原尺寸贴左上角，窗口更宽时右边自然露出渐变） |
| 缺了会怎样 | 静默跳过，界面正常，只是顶部没有图 |
| 为什么分两张 | 浅色主题是深字、深色主题是白字，需要两个方向的遮罩，一张图靠调透明度盖不住两边 |
| 用户能不能自己换 | 能。往 `app\` 里丢一对 `header-light.png` / `header-dark.png` 即可，**不用重新打包**（README 里就是这么写的） |

所以打包时带上这两个文件，等于给用户一个"开箱就有头图"的默认值，而不是必需项。

**`--icon` 和 `--add-data` 缺一不可**，它们管的是两件不同的事：

| 参数 | 管什么 |
|---|---|
| `--icon` | **exe 文件本身**在资源管理器里的图标 |
| `--add-data` | tkinter **窗口标题栏 / 任务栏**的图标 |

Tk 窗口默认永远画自带的羽毛，跟 exe 图标无关。必须把 ico 打进包里，
运行时由 `set_window_icon()` 通过 `sys._MEIPASS` 取到并 `iconbitmap(default=...)`。
少了 `--add-data`，就会出现"exe 图标是对的、窗口左上角还是羽毛"。

`--version-file` 让 exe 的「属性 → 详细信息」里显示版本号而不是一片空白。

> 打包前先确认没有残留进程占着 exe，否则会以
> `PermissionError: [WinError 5] 拒绝访问` 收场：
> `Get-Process 大肥鱼直播姬 | Stop-Process -Force`

### 改版本号要动三处

1. `live_notify.py` 的 `VERSION`
2. `_build/version_info.txt` 里的 `filevers` / `prodvers` / `FileVersion` / `ProductVersion`
3. `CHANGELOG.md` 加一节

漏掉第 2 处的话，界面里显示 1.7.5、exe 属性里还写着旧版本。

> **另外还有三处版本号，别漏**（都是仓库里真实存在的文件，各管一摊）：
>
> | 文件 | 里面的版本号 | 怎么来 |
> |---|---|---|
> | `使用说明.txt` | 第一行的 `vX.Y.Z` | **手写**。它随每个发布包发出去，漏改就是给用户看错版本 |
> | `bucket/dafeiyu-live-notify.json` | `version` / `url` / `hash` | Scoop 清单。有 `autoupdate`，但 `hash` 得靠 `scoop checkver -u` 或手工更新 |
> | `winget/KagurazakaChizuru.DafeiyuLiveNotify*.yaml` | `PackageVersion` / `InstallerUrl` | winget 清单，**同一个版本号要出现在三个文件里**（版本 / 安装器 / locale） |
>
> `_package.ps1` 和 `_submit-winget.ps1` 都是从 `live_notify.py` 里正则抠版本号，
> 这两个不用手改 —— 但这也意味着**第 1 处改错，后面全跟着错**。

### 换图标

### 部署体积（私有 QQ 副本）

Windows 按可执行文件路径区分应用，所以第二实例需要一份**路径不同**的 QQ。
早期做法是整份复制，代价 1.1 GB —— 而 QQ 的 `versions/<ver>/` 装完之后几乎
不再被写入，等于白白复制了一份 Electron 运行时。

现在的做法（详见 [技术文档 §6](技术文档.md#6-会话共存设计独立-qq-副本)）：

| 组成 | 大小 | 说明 |
|---|---|---|
| `qq-napcat-private\` 顶层文件 | 约 8 MB | 真实文件：`QQ.exe`、DLL、`extension\` |
| `qq-napcat-private\versions\*.json` | < 1 KB | 真实文件，QQ 运行时会写它们 |
| `qq-napcat-private\versions\<ver>\` | 0 | **junction** → 系统 QQ 的同名目录 |

> 目录名特意保留 `qq-napcat` 字样（`qq-napcat-private`），这样
> `gui.py` 里 `-like '*qq-napcat*'` 那个停止过滤条件不用改也能匹配。
> 改目录名之前先看 [技术文档 §6.5](技术文档.md#65-停止语义关键安全约束)。

两个启动器在拉起 NapCat 之前都会先跑一次 `_fix-qq-link.ps1`：它从注册表找到
系统 QQ、挑出最新的版本目录、发现联接指错就用 `rmdir` 删掉旧链接（只删链接，
不碰目标）再重建。**QQ 自我升级因此不会把机器人弄挂。**

顺带一提，`napcat\native\` 里打包了**所有平台**的原生模块，Windows 上只用得到
`win32` 的那些。删掉 `linux` / `darwin` 的能省约 70 MB（`napcat` 90 MB → 21 MB）：

```powershell
Get-ChildItem napcat\native -Recurse -File |
  Where-Object { $_.FullName -match 'linux|darwin' -and $_.FullName -notmatch 'win32' } |
  Remove-Item -Force
```

实测删完 NapCat 照常启动（日志里 `Napi2NativeLoader 加载成功`、
`FFmpeg ✓ 使用 Native Addon`、`Platform=win32.x64`）。

### 发 GitHub Release（别漏）

**光推 tag 是不够的。** GitHub 的 Releases 页面只认通过 API 创建的 release；
tag 本身只出现在 Tags 列表里，别人点进 Releases 是**空的** —— 一眼看不出
版本之间改了什么。

```powershell
# 1. 改 CHANGELOG.md，加一节 "## <版本号>"
#    第一行写一句概述，它会被拿去做 Release 的标题

# 2. 提交、打 tag、推
git add -A && git commit -m "chore: 版本升到 x.y.z"
git tag -a vx.y.z -m "x.y.z —— 一句话"
git push origin main && git push origin --tags

# 3. 打包（需要先重新构建 exe）

# 4. 发 Release + 传附件
$env:GH_TOKEN = '<有 repo 权限的 token>'
.\_release.ps1 -Asset dist\dafeiyu-live-notify-vx.y.z.zip
Remove-Item Env:\GH_TOKEN
```

`_release.ps1` 的几个设计取舍：

- **-DryRun 先看一眼**：不调 API，只打印会发出去的标题和正文
- **正文从 `CHANGELOG.md` 抽同名小节**，不另外维护一份。
  单一事实来源，更新记录和 Release 永远不会各说各话
- **附件重名先删再传**，所以重复跑不会炸

> 仓库里**不放任何 token**。两个脚本都只从环境变量 `GH_TOKEN` 读，
> 用完记得清掉。

## 8. 提交与文档维护

### 提交

```bash
git config user.name  "KagurazakaChizuru"
git config user.email "329428985+KagurazakaChizuru@users.noreply.github.com"
```

提交信息用中文，格式 `类型(范围): 一句话`，类型用
`feat` / `fix` / `style` / `docs` / `chore`。
正文写清**为什么**改，尤其是踩过的坑 —— 那才是后来人真正需要的信息。

> ⚠️ **消息里带双引号时，不要写 `git commit -m $msg`。**
> PowerShell 5.1 把变量传给原生命令时，内嵌的 `"` 会让参数被拆成好几个，
> git 会报一堆 `pathspec '...' did not match any file(s)`，而提交根本没发生
> （紧接着的 `git push` 还很容易显示 "Everything up-to-date" 蒙混过关）。
>
> 稳妥写法是把消息写进文件再用 `-F`：
>
> ```powershell
> [System.IO.File]::WriteAllText($mf, $text, (New-Object System.Text.UTF8Encoding($false)))
> git commit -F $mf
> ```
>
> 注意去掉 BOM，否则它会变成提交信息里的第一个字符。
