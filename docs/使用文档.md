# 使用文档 · 大肥鱼直播姬

这一篇写给**用它的人**。不需要懂任何技术，照着做就行。

> 想了解内部原理 → [技术文档](技术文档.md)　想改代码 → [开发文档](开发文档.md)

---

## 1. 它替你做什么

你开播时，它自动往你指定的 QQ 群发一条 `@全体成员`；
你下播时，再发一条（这条默认**不 @ 任何人**）。

**开播时你不需要做任何操作**，程序挂着就行。

它判断"你开播了"靠的是**查你直播间的状态**，不是查你开没开直播软件。这一点很关键：

| | |
|---|---|
| ✅ 能检测到 | OBS、B站直播姬、抖音直播伴侣、手机开播，甚至别人帮你推流 |
| ❌ 不会误报 | 你只是打开了 OBS 在调设备、试麦，房间还没开 |

也就是说，**它只在你房间真的开了的那一刻发通知**，不会提前打扰群友。

---

## 2. 要准备什么

| | 说明 |
|---|---|
| 一台 Windows 10/11 电脑 | 直播推流的那台，程序要一直开着 |
| 一个 QQ 号 | **建议用小号**。它会以这个号的身份在群里发消息 |
| NapCat | QQ 协议端，**本仓库不含**，需要自己下载（见下） |
| 可选：OBS Studio 28+ | 装了的话可以精确到"按下开始推流"那一刻 |

> **关于 QQ 号**：程序会让这个号登录在一份**独立的 QQ 副本**上，
> 和你自己正在用的 QQ 完全不冲突 —— 你的 QQ 照常开着、照常聊天。
> 详见 [技术文档 §6](技术文档.md#6-会话共存设计独立-qq-副本)。

## 3. 第一次使用

### 方式 A：用打包好的文件夹（推荐，不需要装 Python）

去 [Releases](https://github.com/KagurazakaChizuru/dafeiyu-live-notify/releases/latest)
下载最新的 zip，解开。里面是这样：

```
dafeiyu-live-notify-vX.Y.Z\
├── 大肥鱼直播姬.exe      ← 只有这个需要双击
├── 使用说明.txt
└── app\                  程序本体、文档、图标
```

然后：

**第 1 步 · 放 NapCat**

去 [NapCatQQ Releases](https://github.com/NapNeko/NapCatQQ/releases) 下载
`NapCat.Shell.zip`，解压到 `app\napcat\` 目录下（解压后该目录里应该能看到
`NapCatWinBootMain.exe` 之类的东西）。

> 如果别人给你的整合包里已经带好了，跳过这步。

**第 2 步 · 生成私有 QQ 副本**

这一步让 NapCat 用一份**独立的 QQ**，这样它和你自己聊天的 QQ 互不干扰。

在 `app\` 文件夹里按住 Shift 右键 → 「在此处打开 PowerShell 窗口」，然后：

```powershell
powershell -ExecutionPolicy Bypass -File _setup-qq-copy.ps1
```

它会从你已经装好的 QQ 生成一个约 7 MB 的副本（**不是**把 1.1 GB 复制一份），
屏幕上会告诉你结果的。

> **必须先把 QQ 装在电脑上**，这个脚本靠它生成副本。
> 仓库和 Release 里都不含 QQ 本体（那是腾讯的专有软件）。

**第 3 步 · 让机器人登录 QQ**

双击 `大肥鱼直播姬.exe`，点界面上的「开始直播通知」，程序会自动拉起 NapCat。
首次需要在弹出的窗口里**扫码登录你的小号**。

想免去每次扫码：把 QQ 号填进 `app\_account.txt`（一行，纯数字）。

**第 4 步 · 填群号和直播间**

在界面「通知群」标签页里点「刷新」，把机器人已经加入的群加进来；
在「消息与设置」标签页里填你的直播间链接（比如 `https://live.bilibili.com/123456`）
和开播文案。

**第 5 步 · 点大按钮**

回到「运行日志」页，点那个大蓝按钮。看到顶部状态变成
`● QQ 已就绪`、`触发源　直播间 未开播` 就说明它在盯着了。

之后照常开播即可。

## 4. 界面导览

### 顶部状态行

```
大肥鱼直播姬                             ☾ 深色
● QQ 已就绪 2123456789                    未开启
触发源　直播间 未开播 · OBS 未连接 · 快捷键就绪
```

- `● QQ 已就绪` —— 连得上 NapCat 才是绿的，红字说明掉线了（程序会自动重连）
- `触发源` —— 实时告诉你每个信号源现在的状态，开播后这里会变成「直播间 直播中」，
  你可以**亲眼看到检测在工作**
- `☾ 深色` —— 点一下换深色，会记住你的选择（下一节）

### 深色模式

右上角那个 **`☾ 深色`** 点一下就切到深色，再点变回浅色。选择写进 `config.json`
的 `ui.theme`，下次打开还是你选的那个。

深色不是纯黑，是接近黑的中性深灰 —— 纯黑配纯白对比太强，晚上看久了眼睛累。
界面上的其它颜色也都跟着一起转，不需要重启。

### 底部常驻操作栏

整个界面只有**一个**按钮，它固定在**最底下那条栏里**的右侧：

```
┌──────────────────────────────────────────────┐
│ 已开启自动检测（直播间开播 + OBS 推流）          │
│ 快捷键 CTRL+ALT+K 是备用：想手动推一次就按它     │
│ 点一下就开始，之后一直挂着就行。        [开始直播通知] │
└──────────────────────────────────────────────┘
```

左侧那两行是**当前状态**，颜色和含义：

| 颜色 | 含义 |
|---|---|
| 🟢 绿 | 已开启自动检测，你什么都不用做 |
| 🟡 黄 | 没开自动检测，开播时要记得按快捷键 |
| 🔴 红 | 两个都没开，**开播不会通知任何人** |

它一直挂在最底下，切到哪个标签页都在 —— 不用滚回去找按钮。

### 通知发不出去怎么办

程序会自己处理。发失败的群按 **5 秒 → 15 秒 → 45 秒**重试三次（NapCat 掉线
通常十几秒就自动重启回来了，正好赶上）。**已经发成功的群不会重发**，群友不会
收到好几条一样的。

三轮都没成功才会认输，这时会弹一个提示、顶栏亮警告，你可以直接按快捷键手动补发
（不用重开监控）。

「运行日志」页最底下有个**「上次通知」**卡片，随时能看上一批发出去没有：

```
上次通知                                    23:14:09　直播间开播
已发送 3/3　全部成功
```

失败的话这里会是红的。

### 窗口大小和位置会被记住

拖成什么样、挪到哪里，下次打开还是那样。不用每次重新调。

### 四个标签页

| 标签页 | 干什么的 |
|---|---|
| **运行日志** | 程序干了什么一目了然。**出问题先看这里**；最底下是「上次通知」 |
| **通知群** | 加群 / 删群 / 切换 @方式 |
| **触发方式** | 开播怎么判定、UP 主订阅（投稿 / 动态）、下播提示、快捷键 |
| **消息与设置** | 开播文案、封面小图、游戏识别、二次提醒、新投稿与新动态文案、检查间隔、冷却时间 |

改完记得点「保存设置」。

## 5. 日常使用

双击 `大肥鱼直播姬.exe` → 点底栏那个按钮 → 最小化，然后正常开播。

程序支持「打开程序后自动开始监控」（在「消息与设置」→「启动行为」里勾），
勾上之后双击图标就等于直接开始监控，连按钮都不用点。

**下播提示**默认开启，会自动填上本次播了多久：

```
🌙 下播啦，今晚播了 2 小时 15 分钟

谢谢大家陪播～
```

**快捷键**默认 `Ctrl+Alt+K`，任何情况下按一下就手动推一次，作为兜底。
可以在「触发方式」里点「按下组合键设置…」改掉。

### 通知里会自动带什么

发出去大概是这个样子：

```
@全体成员 🔴 开播了兄弟们！

今晚不鸽，来陪我送
正在玩《三角洲》
https://live.bilibili.com/123456
［你的直播间封面小图］

大家快来捧场～
```

**「正在玩《XXX》」是自动识别出来的**，你不用每次改文案。它看的是当前
窗口和直播姬/ OBS 的场景配置——**全程本机读取，不截图、不上传任何画面**。

认不出来的时候，那一行会自动消失，不会变成「正在玩《》」。

在「消息与设置」页有个 **「测试一下现在认成什么」** 按钮，
开个游戏点一下就知道了。要是认错了（比如把你的虚拟形象软件当成游戏），
把它填进下面那个「不算游戏的」框里就行。

**封面**用的是你 B站直播间的封面，程序会压到很小再发，只有几 KB。
不想要就在「消息与设置」里取消勾选。

### 开播后还会再喊一次

默认在开播 **30 分钟**和 **1 小时**各补一条，给第一波没看到的人第二次机会：

```
还在播～ 现在打《三角洲》
https://live.bilibili.com/123456
```

几条保险，免得变成骚扰：

- 只有在直播间**确实还开着**的时候才发
- 本场最多发 3 条（含开播那条），断流重连也不会刷屏
- 默认**不 @ 任何人**

中途换游戏也会补一条「换游戏了，现在打《XXX》」，同样是普通消息，不 @。

### UP 主发新视频 / 新动态也通知你（1.8.0）

「触发方式」页最下面那块，勾上之后填 UID 就行 —— UID 就是空间地址里的那串数字：
`space.bilibili.com/12345678` → `12345678`。

**保存这件事有两半，别漏**：名单里的「添加」是**立刻保存**的，而上面那个
**开关要按「保存设置」**（「触发方式」页和「消息与设置」页最下面各有一个）。
只点开关不保存的话，界面上看着是勾着的，配置里其实还是关的 —— 这是实测踩过的坑，
现象就是"我明明开了，它一条都不推送"。

保存之后**不用重启程序**：下一轮（最多 5 分钟）它就会开始查。第一次查只记下
"当前最新一条"当起点、**不会补发历史**，所以真正会推送的是订阅之后发的下一条。

**动态要额外填一次登录态**（投稿不用）。实测动态接口不登录读不到东西 ——
连 B站官方账号都一样，不是我偷懒：

1. 浏览器登录 B站 → 按 `F12` → `Application`（应用）→ `Cookies`
   → `https://www.bilibili.com` → 找到 `SESSDATA`，复制它的值。
2. 关掉本程序，用记事本打开 `app\config.json`，把值填进
   `subscribe` 里的 `sessdata`，保存。
3. 重新打开 → 「触发方式」页勾上「也通知动态」→ 保存设置。

`SESSDATA` 是**能直接登录你账号的凭据**，所以：日志里它会被打码，
发版打出来的 zip 会拒绝包含它的文件，界面上也不显示（跟控制端口 token 一个口径）。
**别把它贴给任何人**，包括截图。

它大概一个月会失效一次。**失效时不会有任何报错** —— 动态只是安静地不来了，
跟"那个 UP 主最近没发动态"分不出来（这是实测的：拿一个假凭据去打，接口照样
回成功、只是内容为空）。所以想知道凭据还活着没：

    双击 app\1-自检.bat —— 动态开着时它会拿 B站官方号对照读一次，
    读得到就写「登录态有效」，读不到就写「登录态可能已经失效」。

看到失效就照上面三步重新取一个填进去。

```
🔔 某某 更新了

新视频的标题
https://www.bilibili.com/video/BV1xx411c7mD
```

几句话说明白它**不**做什么：

- **不补发历史。** 刚加上去的时候，程序只把"当前最新一条"记成起点，
  一条都不发 —— 否则等于把人家几年的旧投稿一次刷进群。
- **投稿不用登录**；动态要（见上）。动态里的**投稿类**会自动跳过 ——
  它和投稿是同一件事，不跳就会同一个视频报两遍。
- 动态正文太长会**截断在标点处**（约 140 字），想看全文点链接。
- **查得慢。** 默认 5 分钟一次，最低 1 分钟。实测查太勤会被 B站按来源拦掉
  （整个来源一起拒绝，要等它自己恢复），所以别改小。
- **被拦了自己会歇。** 万一还是撞上，它会安静 15 分钟再试，不再按原节奏去敲门 ——
  日志里会写"退避到几点"，那不是坏了。
- 播报是**普通消息**，默认不 @ 任何人（想 @ 得改配置文件里的 `subscribe.at_all`）。

文案分两块：「UP 主发新视频时的文案」用 `{up}`（UP 主名字）、`{title}`（视频标题）、
`{link}`（视频地址）；「UP 主发新动态时的文案」用 `{up}`、`{text}`（动态正文）、
`{link}`（动态地址）。两块都能写多条，用单独一行 `---` 隔开，每次随机挑一条。

### 想让每次说的话不一样

「开播文案」那个框可以写**好几套**，中间用**单独一行 `---`** 隔开：

```
🔴 开播了兄弟们！

{title}
正在玩《{game}》
{link}

---
今天播到几点看心情，来陪我坐会儿

{title}
{room_title}
{link}
```

每次开播随机挑一套，群里不会每次都看到一模一样的话——人对重复内容
是会免疫的。

> 可用占位符：`{title}` `{link}` `{game}` `{time}` `{date}` `{room_title}`
> `{room_desc}` `{hook}` `{tod}` `{weekday}` `{prev_game}`。
> 下播和提醒里还能用 `{duration}`（播了多久）和 `{peak}`（人气峰值），
> 订阅的文案里能用 `{up}`（UP 主名字）和 `{text}`（动态正文）。
> 一共 15 个，每个是什么意思见下一节。
>
> 写错名字（比如 `{game_line}` 这种不存在的）**不会报错**，程序会把那个占位符
> 整个删掉再发 —— 所以模板里少了半句话去群里找原因，先回来看看拼写。

## 6. 常见问题

**Q：开了通知器，我的 QQ 会掉线吗？**
不会。程序跑在一份独立的 QQ 副本上，Windows 把它当成另一个程序，
所以是两个互不干扰的实例。实测你自己的 QQ 8 个进程全程不受影响。

**Q：为什么不做成「检测到 OBS 启动就通知」？**
因为那不是你开播的时刻，你还要调设备。这个选项在「触发方式」里有，
但默认关闭 —— 打开就要做好被群友白提醒一次的准备。

**Q：直播姬 / 直播伴侣能自动检测吗？**
**能，但走的是直播间轮询那条路**（它不看你用什么软件）。
只有「OBS 推流事件」这一种触发方式需要 OBS 自带 websocket，
直播姬虽然是 OBS 内核但没带这个插件，直播伴侣完全封闭。

**Q：群里的 `@全体成员` 没提醒到人？**
机器人不是群主/管理员。跑 `python live_notify.py check` 会告诉你具体哪个群不行，
改用「@指定人」再点「自定义 @名单」逐个填 QQ 号即可。

**Q：会不会泄露我的聊天记录？**
程序只跟 `127.0.0.1:3000` 通信，聊天内容不落盘，日志级别是关的。
唯一的对外请求是查你自己的直播间状态（不带任何身份信息、不走代理），
不喜欢可以在「触发方式」里关掉。

**Q：能不能装在手机上？**
不能，也不需要 —— 你推流用的就是这台电脑，程序必须跟直播软件在同一台机器上，
而且它依赖 Windows 的进程和窗口接口。想在手机上查看/手动触发，
可以把「本地控制端口」打开，用手机浏览器访问（见下）。

**Q：手机上能手动触发吗？**
可以。程序默认在 `http://127.0.0.1:8899/` 开了一个极简控制页，
浏览器打开就能看到状态、点一下手动发送。目前仅限本机访问。

## 7. 出问题了怎么办

**先看「运行日志」页**，绝大多数问题那里都写了原因。

| 症状 | 怎么办 |
|---|---|
| 界面打不开 | 双击 `app\启动界面-调试.bat`，会带控制台启动，能看到报错 |
| 程序卡住关不掉 | 双击 `app\退出全部.bat`，输入 `Y`（只关通知器，**不会动你的 QQ**） |
| `● QQ 未就绪` 一直红 | NapCat 没起来。看日志里 NapCat 那段输出，多半是没登录或端口被占 |
| 开播了但没发 | 看顶部「触发源」那一行。如果显示「直播间 未开播」，说明直播间链接填错了 |
| `@全体成员` 没人被提醒 | 机器人不是群主/管理员，见上方 FAQ |
| 想验证配置对不对 | 双击 `app\1-自检.bat` |
| 想看不真发会发什么 | 双击 `app\2-彩排.bat` |

`app\` 下还带了一组快捷脚本，双击即可，不用敲命令：

```
0-一键启动.bat    打开界面
1-自检.bat        检查配置 / NapCat 连通性 / 群权限
2-彩排.bat        打印将要发送的内容，不真发
3-开始监控.bat    不开界面，直接常驻监控
4-立即发送.bat    立刻发一次
5-查看所有群.bat  列出机器人所在的所有群
```

## 8. 卸载

**绿色免安装**：没有安装程序、不写注册表、不开机自启。

把 `大肥鱼直播姬` 整个文件夹删掉就干净了。
你自己 QQ 的聊天记录在别处，不受影响。

| NapCat 的 WebUI | 已限制为仅本机监听 |
| 聊天内容 | **不落盘**，日志级别已关 |
| 外部请求之一 | 查询你自己直播间的公开开播状态（开启「① 直播间开播时通知」时） |
| 外部请求之二 | 查询你订阅的 UP 主的公开投稿列表（开启订阅时） |
| 外部请求之三 | 查询你订阅的 UP 主的公开动态（开启「也通知动态」时，**带你的登录态**） |
| 登录态 | 只在你自己的 `app\config.json` 里，日志打码、界面不回显、**不会进发版打出来的 zip** |

这两条都默认直连、**不走系统代理**、不携带任何身份信息 ——
不需要登录、不用 Cookie、不读你的 B站账号，读的都是任何人打开网页就能看到的公开数据。
介意的话在「触发方式」里取消对应的勾选即可，其余触发源完全在本地工作。

## 10. 让消息更抓眼（1.7.5）

### 10.1 消息分三层

```
🔴 三分钟，看完不满意再走        ← 群文案（{hook}，18 条随机）
                                   
【空洞骑士】今天打完螳螂领主      ← 直播间真实标题（{room_title}）
晚上八点开播，打到哪算哪          ← 直播公告（{room_desc}）
正在玩《艾尔登法环》              ← 游戏识别
https://live.bilibili.com/xxxx    ← 你的直播间
```

**群文案**是顶端那句勾人的话，跟「开播通知文案」分开两块写 —— 改一句开场白
不用动整个模板。「消息与设置」页有独立的输入框，留空就用内置的 18 条。

**直播间标题和公告**是程序从 B站读的，**你改了直播间的标题，通知里就跟着变**，
不用手动同步。公告里的 HTML 会被剥掉，太长会在句号处截断。

### 10.2 可用的占位符

| 占位符 | 是什么 |
|---|---|
| `{hook}` | 群文案（从池子里随机挑一句） |
| `{room_title}` | 你此刻在直播间的真实标题 |
| `{room_desc}` | 直播公告（HTML 会被剥掉，太长在标点处截断） |
| `{title}` | 配置里写死的那句（老写法，留着兼容） |
| `{game}` | 正在玩的游戏 |
| `{duration}` `{peak}` | 本场时长 / 人气峰值（下播用） |
| `{tod}` `{weekday}` | 时段（早上/下午/深夜…）、星期几 |
| `{prev_game}` | 换游戏时的上一个游戏 |
| `{up}` | UP 主的名字（只在订阅的播报里有值） |
| `{text}` | 动态正文（只在「UP 主发新动态」的文案里有值，超长会在标点处截断） |
| `{link}` `{time}` `{date}` | 直播间地址 / 时间 / 日期 |

**别写死「今晚」「深夜」这类词** —— 早上八点下播就成了笑话。用 `{tod}`。

**拿不到的值，那一整行会自动消失** —— 所以放心把「最后在玩《{game}》」
单独放一行，认不出游戏时它不会渲染成「最后在玩《》」。

### 10.3 换游戏的播报

两个参数，管的是不同的事：

- **换游戏确认**（默认 20 秒）—— 新游戏要稳定这么久才播报。防止切窗口、
  加载地图时的瞬间抖动被当成换游戏。
- **换游戏冷却**（默认 0 分钟）—— 两条播报之间至少隔多久。

默认值下，**你玩几分钟换游戏会正常播报**。以前冷却默认 5 分钟，正常换游戏
会被压掉，群里还以为你在玩上一个。

## 10.4 测试窗口：先看，再发（1.8.0）

「消息与设置」页最下面的「测试」里有个「预览将发送的内容」—— 点开就是一个
**测试窗口**，把此刻各类通知会长什么样全列出来，**一条都不会发出去**：

- 开了哪几类就列哪几类（开播、下播、二次提醒、换游戏、新投稿、新动态）
- 「**换一批**」重新随机挑文案 —— 池子里每类有十几句，连着点几次就知道
  自己喜欢哪套，不用等真的开播才知道
- 想看"标题没取到时长什么样"，里面专门列了一条

同一张卡片上还有「私聊发开播 / 下播 / 新投稿 / 新动态」四个按钮：
**真的会发出去，但只发到你填的那个 QQ，不进任何群**。填你自己的号 ——
QQ 一般不允许给机器人自己发私聊。

## 11. 先试试看，别打扰群友

「消息与设置」页最下面有一块「测试」：

**预览将发送的内容** —— 只渲染给你看，**一条都不会发出去**。开播、下播、
二次提醒、换游戏各来一条，连「取不到标题时」长什么样都能看。

**私聊发开播 / 私聊发下播** —— **真的会发，但只发到「测试接收 QQ」**，
群里没有任何动静。填你自己的号，别填机器人的号（QQ 一般不允许给自己发私聊）。

下播那条里的时长和峰值是编的，只为看格式。

## 12. 托盘图标

程序会在右下角放一个托盘图标。

- **点 X** = 收进托盘，**程序继续跑**，任务栏不再占位
- **右键托盘** = 显示/隐藏主界面 · 开始/停止监控 · **退出**
- **左键点托盘** = 显示主界面

**退出只走托盘菜单那一条**，免得误点 X 就把监控关了。

> 新图标默认会被 Windows 收进 `^` 折叠区。点一下任务栏那个 `^`，
> 把它拖到可见区，以后就在外面了。
